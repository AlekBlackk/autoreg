# RegLog — журнал регистраций

Расширение Chrome (Manifest V3), которое помогает регистрироваться на сайтах: берёт адрес временной почты, генерирует имя/логин/пароль, заполняет форму регистрации на активной вкладке, показывает входящие письма с кодом подтверждения и ведёт локальный журнал аккаунтов.

## Установка

1. Открыть `chrome://extensions`.
2. Включить «Режим разработчика» (переключатель в правом верхнем углу).
3. Нажать «Загрузить распакованное» и выбрать корень репозитория (там же лежит `manifest.json`).

При установке расширение **не запрашивает доступ ни к одному сайту** — Chrome не покажет ни одного предупреждения о доступе к сайтам на этом шаге.

## Что делает

- Берёт адрес временной почты у одного из семи активных сервисов, с автоматическим переключением на следующий, если домен текущего сервиса не устраивает сайт.
- Генерирует имя, логин и пароль (три пресета: `strong`/`safe`/`legacy`).
- Заполняет найденные поля формы на активной вкладке — с обходом Shadow DOM и поддержкой React-подобных полей.
- Показывает входящие письма выбранного ящика, распознаёт код подтверждения или ссылку; подсветка нового письма, тост и счётчик на вкладке «Ящик» работают только пока попап или боковая панель открыты — фонового воркера для этого нет, поэтому после закрытия окна расширения сигнала не будет.
- Ведёт локальный журнал аккаунтов с поиском, копированием и экспортом в JSON/CSV.

## Чего не делает и не будет делать

- **Не отправляет форму сама.** Кнопку «Зарегистрироваться» всегда нажимает человек — расширение технически не вызывает `submit()`, `requestSubmit()`, `click()` на элементах формы и не эмулирует `Enter`.
- **Не решает и не обходит капчу** — ни распознаванием, ни через сторонние сервисы.
- **Не делает пакетную регистрацию.** Переключение почтового провайдера — разовое действие для текущего аккаунта, а не перебор ради массового создания учёток. Циклов по спискам сайтов, расписаний и фоновых прогонов нет.
- **Не принимает одноразовые SMS.**
- **Не отправляет никакой телеметрии** и не делает сетевых запросов, кроме обращений к API временной почты из списка ниже.

## Сервисы временной почты (порядок по умолчанию)

1. **mail.tm** (`api.mail.tm`) — основной.
2. **mail.gw** (`api.mail.gw`) — тот же API на других доменах, спасает, когда домены mail.tm в блоклисте сайта.
3. **Maildrop** (`api.maildrop.cc`) — ящик существует заранее, без сетевого запроса на создание. **Инбокс публичный**: письма читает любой, кто знает адрес, поэтому локальная часть адреса всегда содержит непредсказуемую случайную часть.
4. **Guerrilla Mail** (`api.guerrillamail.com`) — домены старые, часто в блоклистах, поэтому последний из проверенных по порядку.
5. **DustMail** (`dustmail.net`) — ящик живёт 30 минут, адрес выдаёт сам сервис (выбрать локальную часть нельзя). Читается по capability-id (uuid) в пути, поэтому знание адреса ещё не даёт доступа к письмам. **Используется недокументированный front-end API** — тот же `https://dustmail.net/api/*`, которым пользуется их собственный сайт, без ключа и авторизации. Схема ответов снята вживую, официальные доки её не публикуют, поэтому адаптер может сломаться без предупреждения при любом обновлении их сайта; на этот случай хватает переключения на предыдущие сервисы.
6. **Mail.cx** (`mail.cx`) — адрес на одном из системных доменов сервиса (домен выбирается случайно), ящик не создаётся заранее: почта на адрес принимается сразу. **Инбокс публичный**: письма читает любой, кто знает адрес, поэтому локальная часть всегда содержит непредсказуемую случайную часть (сервис ограничивает её 20 символами). Письма хранятся час. **Используется недокументированный front-end API** — тот же `https://mail.cx/v1/*`, которым пользуется их собственный сайт, без ключа и авторизации; схема снята вживую, поэтому адаптер может сломаться при обновлении их сайта — тогда хватает переключения на предыдущие сервисы. Пустой ящик сервис отдаёт не сразу, а через ~25 секунд (long-poll), поэтому кнопка «Обновить» ждёт не дольше трёх секунд.
7. **TempMail.lol** (`api.tempmail.lol`) — адрес на случайном домене из пула сервиса; к выбранной локальной части сервис дописывает ещё шесть случайных символов. Ящик читается по токену, а не по адресу, поэтому знание адреса доступа к письмам не даёт. Бесплатный ящик живёт час. Используется документированный публичный v2 API бесплатного тарифа, без ключа.

**DropMail временно отключён**: публичный API перестал принимать самостоятельно выпущенные токены (сервер отвечает `403 invalid_token`/`legacy_token_disabled`), рабочего ключа нет. Адаптер помечен `disabled` в списке сервисов (вкладка «Настройки» показывает его как «адаптер не реализован» и не даёт включить) и исключён из порядка по умолчанию — код и тесты остались в репозитории на случай появления легального способа авторизации. Host-permission `https://dropmail.me/*` из манифеста при этом убран: пока адаптер выключен, разрешение ничего не даёт, а расширение просит на один домен больше, чем использует. Оживёт адаптер — вернётся и разрешение.

Порядок и включение/выключение сервисов настраиваются на вкладке «Настройки».

Перед первым обращением к сервису в сессии браузера делается один дешёвый проверочный запрос (`GET /domains` у mail.tm/mail.gw, `ping` у Maildrop): лежачий сервис отваливается сразу, а не после полного цикла создания ящика с восьмисекундными таймаутами. У Guerrilla Mail, DustMail, Mail.cx и TempMail.lol такой запрос не делается — у них создание ящика само по себе самое дешёвое обращение, отдельная проверка только удвоила бы трафик.

## Где лежат данные

Всё — в `chrome.storage.local` (журнал, черновики, настройки, отказы) и `chrome.storage.session` (кулдауны провайдеров, отметки пройденного health-check, активная вкладка, ключ шифрования журнала при включённом мастер-пароле). Наружу уходят только запросы к API временной почты из закрытого списка `host_permissions` манифеста — это ровно семь доменов, перечисленных в разделе выше (`api.mail.tm`, `api.mail.gw`, `api.maildrop.cc`, `api.guerrillamail.com`, `dustmail.net`, `mail.cx`, `api.tempmail.lol`). Никаких других сетевых обращений расширение не делает.

## Доступ к сайтам

При установке — ноль запросов доступа. Если форма регистрации встроена кросс-доменным `<iframe>` (типично для Auth0, Firebase Auth и аналогичных), расширение предложит двухшаговый запрос доступа: сначала право на список фреймов страницы (`webNavigation`), затем — явное согласие на конкретные origin, которые вы увидите текстом перед подтверждением. Права запрашиваются один раз на origin и переиспользуются на всех сайтах с тем же провайдером авторизации. Отозвать в любой момент — вкладка «Настройки» → «Доступ к фреймам».

## Мастер-пароль журнала

Опциональная защита (вкладка «Настройки» → «Защита журнала»): при включении журнал шифруется целиком (AES-GCM 256, ключ выводится PBKDF2-SHA256 с 600 000 итераций — текущая рекомендация OWASP). Параметры KDF и соль хранятся внутри самого шифроблоба, поэтому журналы, записанные прежними версиями (310 000 итераций), продолжают открываться, а число итераций можно поднимать и дальше. **Чего мастер-пароль не даёт**: пока журнал разблокирован в текущей сессии браузера, ключ шифрования лежит в `chrome.storage.session`, и другое расширение с правами отладки или локальный вредонос на этом же профиле сможет его достать. Защита рассчитана на случай «кто-то получил доступ к профилю Chrome оффлайн», а не на активный вредонос в работающей системе. Забытый пароль — потерянный журнал без возможности восстановления.

## Почему временная почта не годится для важных аккаунтов

Временный адрес общедоступен по своей природе — сервис может его переиспользовать, а у части провайдеров (Maildrop) инбокс читает любой, кто узнал адрес. RegLog создан для одноразовых тестовых регистраций, а не для аккаунтов, которыми вы дорожите.

## Тесты

```
npm test
```

Требуется Node 21 или новее. Зависимостей нет — `npm install` не нужен, `package.json` существует только ради этой команды (`private: true`, в реестр ничего не публикуется). Тесты гоняются встроенным раннером Node по `test/node/*.test.mjs`; путь передан кавыченным глобом, потому что раскрывать его должен сам Node: аргумент-каталог (`node --test test/node/`) резолвится как один модуль и падает с `MODULE_NOT_FOUND`.

## Известные ограничения

- Закрытые (`mode: 'closed'`) Shadow DOM недостижимы — это ограничение платформы, а не баг расширения.
- `activeTab` не покрывает кросс-доменные `<iframe>` — отсюда механика двухшагового запроса прав выше.
- Сайты с медленной или отложенной отрисовкой формы могут потребовать повторного нажатия «Проверить поля» после того, как форма реально появилась в DOM.
